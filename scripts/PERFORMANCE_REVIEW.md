# Vehicle Search Performance Review

## 1. Technologies Used

- ASP.NET Core (.NET 10)
- Entity Framework Core
- PostgreSQL
- IMemoryCache

## 2. Filtering, Sorting and Pagination

I added filtering to the Vehicles API using `IQueryable`.

Users can filter vehicles by brand, model, year, price, color and availability.

I also added sorting by price, model and year.

Pagination allows users to choose the page number and page size.

The filtering, sorting and pagination are done in the database instead of loading all vehicles into memory.

## 3. Caching

I used `IMemoryCache` to make repeated requests faster.

- Vehicle lists and vehicle details are cached.
- Sliding expiration is 2 minutes.
- Absolute expiration is 5 minutes.
- The cache is cleared when a vehicle is added, updated or deleted, or when a reservation changes vehicle availability.

## 4. Performance Testing

I used `curl` to measure the API response time with and without caching.

| Test | Average Response Time |
|---|---|
| Without Cache | 13.50 ms |
| With Cache | 7.45 ms |

Caching improved the average response time by about **44.8%**.

I tested with 3 vehicles, so the results may be different with a larger database.

## 5. SQL and Database Index

I checked the SQL queries generated by Entity Framework Core.

- `WHERE` is used for filtering.
- `ORDER BY` is used for sorting.
- `LIMIT` and `OFFSET` are used for pagination.
- `COUNT` is used to get the total number of vehicles.

I also created a database index on Brand, AvailabilityStatus and Price.

I used `EXPLAIN ANALYZE` to check the query performance.

Results:

- Index Scan was used.
- 2 vehicles matched the search.
- Query execution time was 0.073 ms.

The index can make searching faster, but it also uses extra storage and adds some work when saving data.

## 6. Testing

I wrote tests for:

- Filtering and combined filters
- Sorting and pagination
- Invalid inputs
- Cache hits and misses
- Cache expiration
- Cache invalidation

I also fixed the reservation caching problem so the vehicle list updates after creating or cancelling reservations.

## 7. Conclusion

I added advanced filtering, sorting, pagination and caching to the Vehicles API.

Caching made repeated requests faster in my tests, and the database index was successfully used by PostgreSQL.

The API now supports more flexible vehicle searches.
